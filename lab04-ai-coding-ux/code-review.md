## รายละเอียดข้อตรวจพบจากการรีวิว (Review Comments)

### Comment 1: เมธอด `issue_product()` — บรรทัดที่ 18-20
* **ทำไมถึงผิด**: ตรวจสอบเงื่อนไขตัดสต็อกบกพร่อง โค้ดใช้ `if item["stock"] < amount:` ซึ่งหากสินค้ามีสต็อก 5 ชิ้น และลูกค้าสั่ง 5 ชิ้น โค้ดจะยอมให้ตัดสต็อกจนเหลือ 0 ได้ แต่หากค่า `amount` ติดลบ (เช่น -10) เงื่อนไขนี้จะไม่ดักจับ ทำให้สต็อกถูกบวกเพิ่มแทนที่จะลดลง
* **กรณีที่จะพัง (Breaking Case)**: เรียก `issue_product("P01", -10)` โดยสินค้า P01 เดิมมีสต็อก 5 ชิ้น ผลลัพธ์สต็อกจะกลายเป็น `5 - (-10) = 15 ชิ้น` ทำให้เกิดการแฮกเพิ่มสต็อกสินค้าในคลังโดยมิชอบ
* **ทางแก้**: เพิ่มการตรวจจับค่าขอบเขตด้านล่าง: `if amount <= 0: raise ValueError("จำนวนที่จ่ายต้องมากกว่า 0")`

### Comment 2: เมธอด `issue_product()` — บรรทัดที่ 26-28
* **ทำไมถึงผิด**: เงื่อนไขการแจ้งเตือนสต็อกต่ำขัดต่อข้อกำหนด (Specification Mismatch) โค้ดใช้เครื่องหมายน้อยกว่าอย่างเดียว `if item["stock"] < item["threshold"]:` ซึ่งหากสินค้ามีสต็อกลดลงมาเท่ากับค่าเกณฑ์พอดี (เช่น สต็อกเหลือ 5 และเกณฑ์คือ 5) ระบบจะไม่ยอมส่งการแจ้งเตือน
* **กรณีที่จะพัง (Breaking Case)**: สินค้า P01 กำหนด `threshold = 5` และถูกจ่ายสินค้าจนเหลือสต็อกคงเหลือ 5 ชิ้นพอดี ผู้จัดการคลังสินค้าจะไม่ได้รับอีเมลหรือ SMS เตือน ทำให้ไม่สั่งสินค้ามาเติมจนของหมดคลังในที่สุด
* **ทางแก้**: เปลี่ยนตัวดำเนินการเปรียบเทียบเป็นน้อยกว่าหรือเท่ากับ: `if item["stock"] <= item["threshold"]:`

### Comment 3: เมธอด `report_value_by_category()` — บรรทัดที่ 34-36
* **ทำไมถึงผิด**: เสี่ยงต่อการทำงานล้มเหลวด้วยข้อผิดพลาด Zero Division หรือ KeyError เมื่อคลังสินค้าไม่มีรายการสินค้าในหมวดหมู่นั้น หรือสินค้าดิจิทัลไม่มีฟิลด์ `stock`
* **กรณีที่จะพัง (Breaking Case)**: หากในระบบมีสินค้าดิจิทัล (`DigitalProduct`) อยู่ใน Dictionary ซึ่งไม่มีคีย์ `"stock"` การเรียกใช้ `item["stock"] * item["price"]` จะเกิดข้อผิดพลาด `KeyError: 'stock'` ทันที ส่งผลให้ระบบล่มทั้งระบบ
* **ทางแก้**: ตรวจสอบประเภทสินค้าหรือใช้ `.get("stock", 0)` เพื่อความปลอดภัย

### Comment 4: คลาส `InventorySystem` — ปัญหา Concurrency ในสภาพแวดล้อม Multi-threaded
* **ทำไมถึงผิด**: ตัวแปร `self.inventory` เป็น In-memory Dictionary ธรรมดาที่ไม่มีกลไก Lock หรือ Synchronized เมื่อมี 2 เธรดเข้ามาตัดสต็อกสินค้าชิ้นเดียวกันในเสี้ยววินาทีเดียวกัน จะเกิดภาวะ Race Condition (Check-then-Act bug)
* **กรณีที่จะพัง (Breaking Case)**: สต็อกเหลือ 1 ชิ้น เธรด A และเธรด B สั่งซื้อพร้อมกัน ทั้งสองเธรดอ่านสต็อกได้ 1 ผ่านเงื่อนไขทั้งคู่ แล้วหักลบสต็อกพร้อมกัน ทำให้สต็อกสุดท้ายกลายเป็น `-1 ชิ้น` (Overselling)
* **ทางแก้**: นำ `threading.Lock()` มาครอบในบล็อกการตรวจสอบและหักลบสต็อก หรือใช้ระบบฐานข้อมูลที่มี Transaction Isolation Level
